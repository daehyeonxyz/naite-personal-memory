# naite 사용자 대면 산출물 품질 기준 (QUALITY.md)

이 파일은 naite 온보딩에서 사용자가 읽는 카피와, 사용자가 외부 AI 에서 가져오는 메모리 export 의 **품질 바**다. 단일 진실원이다. `.claude/skills/naite/start.md` 와 `docs/migrate-prompt.md` 는 기준을 여기서 인용하고 본문에 다시 적지 않는다.

원칙은 하나다. **품질을 에이전트가 매번 잘 쓰기를 바라서 얻지 않는다.** 고정 카피는 동결하고, 가변 입력(메모리 export)은 아래 루브릭으로 pass/fail 판정해 미달이면 되돌려 보낸다. 판단은 열린 글쓰기가 아니라 이항(통과/미통과) 체크다.

이 파일은 `docs/CONTEXT.md`, `docs/CONVENTIONS.md` 와 같은 **shared 문서**다 (Codex 로 미러되지 않는다. 두 도구가 같은 파일을 읽는다).

---

## 1. Onboarding copy rubric

`start.md § 1 모델 설명` 의 고정 카피가 충족해야 하는 기준이다. 카피는 에이전트가 매번 새로 쓰는 게 아니라 그대로 출력하는 동결 블록이며, 아래를 전부 만족할 때만 통과한다.

- **COPY-1 고정 블록:** start.md 가 "30초로 설명한다" 같은 지시문이 아니라, 사용자에게 그대로 보여줄 문장을 코드 블록 안에 담는다. 지시문만 있으면 실패다.
- **COPY-2 가치 명제 양면:** 첫 줄에 두 면이 모두 있다. (1) 개인의 지식·경험을 모아두는 저장소, (2) 그 사람의 에이전트들이 함께 읽는 공유 맥락. 저장소 면만 있으면 실패다.
- **COPY-3 용어를 내용물로 정의:** 여섯 용어를 비유가 아니라 **무엇이 그 안에 들어가는지**로 정의한다. 비유 단어는 라벨로만 쓴다.
  - roots: 원본 자료(대화 export, 강의 노트, 논문, 아티클)가 손대지 않은 채 들어가는 곳
  - tree: roots 를 소화해 만든, 서로 wikilink 로 연결된 위키 페이지 공간
  - 줄기 trunk: 그 나무의 목차이자 뼈대 페이지 (여기서 가지가 뻗어 나간다)
  - 잎 leaf: 사용자 본인의 지식과 경험을 적은 페이지 (위키백과처럼 잎끼리 link 로 이어진다)
  - 열매 fruit: 사용자가 내린 결정과 그때 얻은 통찰을 적은 페이지
  - 나이테 rings: 저장소가 시간에 따라 쌓이고 자라온 기록
  - 한 용어라도 다른 비유로 설명하면(예: "이해가 링크됨", "성장 기록") 실패다.
- **COPY-4 roots vs tree + 멀티 트리:** roots 와 tree 가 다른 것임을 명시하고, "기록하는 내용의 종류에 따라 나무를 여러 개 만들 수 있다" 를 적는다. 둘 중 하나라도 빠지면 실패다.
- **COPY-5 줄기 포함:** 줄기(trunk) 정의가 카피에 있다. 빠지면 실패다 (가장 뼈대가 되는 페이지인데 이전 카피에서 누락됐다).
- **COPY-6 금지 토큰:** 카피에 다음이 없어야 한다. "맥"(veins), "trade-off", em dash "—". 그리고 정의 없이 차이만 주장하는 슬로건 단독("저장 ≠ 축적" 만 쓰면 실패, 한 줄 구체 풀이가 붙으면 통과). 열매 정의에는 "통찰" 이 있고 "trade-off" 가 없어야 한다.
- **COPY-7 응답 스타일:** `CLAUDE.md § 응답 스타일` 준수. 존댓말, 완결 서술문(명사 종결 금지), em dash 금지, 영어 jargon 은 한국어로 한 번 풀어쓴다. 줄 단위로 점검 가능하다.

## 2. Migration export rubric

`docs/migrate-prompt.md` 가 외부 AI 에서 끌어내야 하는 export 의 구조·깊이 기준이다.

- **PROMPT-1 자기소개 먼저:** 가장 먼저 끌어내는 섹션은 "나는 누구인가"(배경, 역할, 전공·분야, 현재 국면)다. "배운 것" 으로 시작하면 실패다.
- **PROMPT-2 배운 것은 깊이 우선:** "배운 것" 이 분량 1순위이고, 평탄한 목록이 아니라 주제별로 여러 필드를 강제한다 (핵심 개념/메커니즘 → 하위 개념 → 개념 간 관계 → 출처 → 내가 이해한 방식). 이 섹션에서 한 문장 항목을 명시적으로 금지해야 통과한다.
- **PROMPT-3 섹션 집합 고정:** 정확히 0 나는 누구인가 / 1 배운 것(깊게) / 2 결정과 통찰 / 3 프로젝트 / 4 반복 관심사 / 5 선호·작업 방식. **금지:** "미해결 질문"(schema home 없음, 사용자 제외 지시), "trade-off"(2번 제목·본문 어디에도).
- **PROMPT-4 깊이는 메커니즘으로 강제:** 형용사("구체적으로")가 아니라 측정 가능한 게이트가 있어야 한다 (예: "1번이 전체 분량의 절반 이상", "항목당 한 문장 금지, 문단으로 전개") + 출력 전 self-check. "얕게 요약하지 마" 한 줄만 있으면 실패다.
- **PROMPT-5 원본자료 경로:** 메모리 회상 대신/함께 실제 1차 자료(강의 노트, 슬라이드, 논문 PDF, 전체 대화 export)를 넣는 경로를 프롬프트나 start.md 가 제시한다. 입력 종류가 메모리 distillation 뿐이면 실패다.
- **PROMPT-6 원본자료 마커:** 주제별로 원본 보유 여부를 `[있음]`/`[없음]` 로 표시하게 해, 워크플로가 읽을 수 있는 깊이 triage 신호를 만든다. 주제 제목만 적고 "(원본 자료 필요)" 로 표시한 경우는 [없음] 과 동일하게 취급한다.
- **PROMPT-7 schema-agnostic 유지:** "순수 Markdown 한 덩어리, 앱별 태그·메타데이터 금지" 를 유지한다 (kind/subject/facet 변환은 ingest 가 전담). naite 스키마 토큰을 프롬프트에 넣으면 실패다.

## 3. Import 검수 게이트

`start.md` 에서 export 를 받은 직후, ingest 로 넘기기 **전에** 돌리는 pass/fail 게이트다. 아래 중 **하나라도 해당하면 ingest 로 넘기지 않고** 사용자에게 보완(또는 원본자료 첨부)을 요청한다.

- (a) section 0 "나는 누구인가" 가 비어 있다.
- (b) "배운 것" 이 전체 분량의 절반 미만이거나, 항목당 한 문장뿐이다.
- (c) 주제에 하위 개념·관계가 없다 (위키 페이지로 펼칠 깊이가 안 됨).
- (d) secrets/PII 가 섞여 있다 (`capture.md § 4` 검사와 별개로 게이트에서도 본다).
- (e) "trade-off" / "미해결 질문" 같은 옛 프롬프트 잔재가 섞여 있다.

게이트 실패 시 되돌리는 보완 지시 예: "section 0 을 채우고, 배운 것의 항목 N개를 문단으로 전개해 다시 생성하거나, 원본 자료를 첨부해 주세요."

선택적 사후 회수: `/naite care --check` 에 "roots/conversations/ 의 온보딩 export 가 자기소개 마커 없이 들어왔는지" 를 플래그하는 결정적 점검을 두면, 게이트를 우회한 경우를 사후에 잡는다 (스키마 가비지 컬렉터와 같은 cadence-recovery 철학).

## 4. Leaf-page depth rubric (OUTPUT)

`ingest`/`grow` 가 `tree/` 에 쓰는 leaf 페이지가 충족해야 하는 **깊이** 기준이다. import 게이트(§ 3)가 입력 export 의 깊이를 강제하듯, 이 루브릭은 **출력 페이지**의 깊이를 강제한다. 입력에만 걸어 둔 깊이 계약이 ingest 경계를 넘으면서 사라지지 않게 막으려는 것이다. 지금까지 QUALITY.md 는 입력만 판정했고, 출력 leaf 깊이는 "에이전트가 매번 깊게 써 주기를 바라는" 상태로 돌아가 있었다. 이 절이 그 비대칭을 닫는다.

- **LEAF-1 메커니즘 보존:** named 구조(개념, 프레임워크 축, 컴포넌트, 페르소나, 발견)마다 그것이 *어떻게* 작동하는지를 본문에 보존한다. 이름만 나열하고 설명을 미루면 실패다.
- **LEAF-2 한 문장 stub 금지:** leaf 는 한두 문장 요약이 아니라, 하위 개념과 개념 사이의 관계를 담은 문단으로 구성한다 (§ 2 PROMPT-2 가 입력에 요구한 깊이와 대칭).
- **LEAF-3 연결:** 최소 한 개의 load-bearing wikilink(설명 산문이 붙은 link)로 나무의 다른 페이지에 잇는다. orphan 페이지는 실패다.
- **LEAF-4 "원본 필요" 의 정직한 사용:** "원본 필요 / 원본 자료 필요" 표시는 ingest 한 소스에 **실제로 없던** 자료에만 쓴다. **소스에 있던 자료를 설명하지 않고 건너뛰는 대체물로 쓰면 실패다.** project/synthesis 페이지가 transcript 에 있던 메커니즘을 "원본 필요" 로 미루는 것이 대표적 실패 클래스다 (dogfood 에서 zipzoom, fde-domain-framework 가 이 경우였다).

미달 시: 그 항목을 stub 으로 정직하게 두되 `seeds.md` 에 깊이 보강 후보로 적고, **소스에 있던 자료라면 미루지 말고 펼쳐 쓴다.**

강제 결선은 Phase 2 다: `lint-ontology.py` 에 본문 길이·wikilink 수 floor 미만을 잡는 결정적 backstop 을 두고(blocking 여부 결정, course-* 한정 스코프 해제), `ingest.md § 5` 가 생산 시점에 이 루브릭을 호출하게 한다. 지금은 바를 명문화해 둔다.
